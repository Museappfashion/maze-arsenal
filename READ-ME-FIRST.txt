MAZE ARSENAL — DEVELOPER DASHBOARD FIX
===========================================

These are normal source files. No installer.

REPLACE
-------
1. src/services/developerAnalytics.js
2. api/developer-usage.js
3. api/developer-analytics.js
4. supabase/developer-analytics.sql

ADD
---
5. api/developer-health.js
6. supabase/CHECK-DEVELOPER-ANALYTICS.sql
7. VERCEL-SETTINGS.txt

INSTALL ORDER
-------------
1. Copy/replace the files above in your repo.

2. In Supabase:
   SQL Editor -> run:
     supabase/developer-analytics.sql

3. Then run the read-only verification:
     supabase/CHECK-DEVELOPER-ANALYTICS.sql

   Expected first row:
     usage_table_exists        true
     server_rpc_exists         true
     service_role_can_execute  true

4. In Vercel -> Settings -> Environment Variables, confirm:
     VITE_SUPABASE_URL
     VITE_SUPABASE_PUBLISHABLE_KEY
     SUPABASE_URL
     SUPABASE_SECRET_KEY
     DEVELOPER_DASHBOARD_KEY

   SUPABASE_SERVICE_ROLE_KEY is also accepted as a legacy fallback.

5. Supabase:
     Authentication -> Anonymous Sign-Ins -> ON

6. Redeploy Vercel after changing environment variables.

7. Visit:
     https://mist-maze.com/?developer=1

8. Type the exact DEVELOPER_DASHBOARD_KEY value.

WHAT THIS FIXES
---------------
- Removes schema drift: developer-analytics.sql now matches the secure
  server-only tracking architecture.
- Browser analytics always goes through /api/developer-usage.
- Serializes analytics session creation so simultaneous events do not race.
- Retries once after an expired Supabase session.
- Uses keepalive so end-of-run analytics are less likely to be lost.
- Supports modern SUPABASE_SECRET_KEY and legacy
  SUPABASE_SERVICE_ROLE_KEY.
- Dashboard no longer depends on enumerating every Supabase Auth user.
- Dashboard totals are based on actual tracked rows.
- Server errors now tell you whether the missing piece is:
    dashboard key,
    Supabase server credentials,
    database migration,
    user authentication,
    or analytics RPC.
- Adds /api/developer-health for private server/database diagnostics.

SECURITY
--------
Never put SUPABASE_SECRET_KEY or DEVELOPER_DASHBOARD_KEY in frontend code.
Never name the secret VITE_SUPABASE_SECRET_KEY.
